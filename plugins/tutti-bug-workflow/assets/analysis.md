## 按独立字段回填

遵循 [字段契约](../references/report-fields.md)：结论 → 分析结论；因果链 → 根因分析；假设/测试/复现 → 排查验证；SHA/工作区 → 代码基线；文件/行号 → 相关代码；候选建议 → 修复方案（未评审）；现场问答 → QA/RD沟通；缺口/恢复条件 → 待核实与阻塞。完整分析保存在本地档案，各字段写职责内摘要；附件按 [集中日志规则](../references/registration-logs.md#日志文件与附件数量) 提交，修复前排查不写成修复后的验证结果。

## 回填摘要

结论：已确认 / 原因未确认。

已确认时用两到四句说明：触发条件 → 首个错误状态及根因 → 传播路径 → QA 可见现象；附必要的影响范围。
未确认时简述：已验证事实 → 仍成立的假设 → 阻止确认的缺口 → 本轮问题或恢复条件。
关键证据：一到三条可定位的代码、日志、测试或截图引用，注明目标、环境及相关版本。

WebMCP 执行记录：实际宿主入口／发现能力与工具 schema／页面及 Account 关联依据／逐次查询参数和返回窗口／记录实际时间与重复次数／截断及未覆盖级别／相关日志与 DOM 观测时间／证据文件。空配置、工具不可用、原生读取失败和成功但覆盖不足分别记录。
Web 日志自动采集完成情况：判断需要后本轮实际执行的截图匹配／原生查询／必要可见 DOM／保存与回填结果；未完成时记录真实尝试、阻塞证据与恢复条件。不能只填写「需要补日志」而结束，也不要求 QA 再次询问或重复确认已有授权。
Web 固定流程结果：提问时间／可信来源或接收时间近似／时区／固定前 10 分钟窗口／采集延迟／全级别查询及分级补查／窗口内全部取得记录与聚合边界限制／实际原文件或 web-logs.log／SHA-256／上传 token 与附件回读结果。条数和未截断不能替代窗口及完整性说明。
Server 日志判断与实际采集：必需／建议补／无需追加／待判断；对应候选、缺失观察、Tutti CLI能力发现与真实调用、AWS适用性/授权恢复、原问题窗口、成功/失败类别、实际覆盖/分页/截断、server-logs.log摘要/file token/回读、阻塞与恢复条件。不能只写建议。
Computer 日志判断：必需／补充／无需采集／待判断；参与边界／候选原因／故障目标与环境／期望状态或事件／已有替代证据／来源与实际覆盖／取得证据后的验证动作。仅确认来源不参与时标记不适用，必要采集受阻另存维护侧。

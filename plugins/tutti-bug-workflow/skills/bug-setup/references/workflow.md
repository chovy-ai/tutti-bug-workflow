# 工作流

| 场景 | 面向 | 交付 | 写入的字段 |
|---|---|---|---|
| `bug-investigate` | QA | 登记 Bug，带全现场日志与上下文 | Bug 描述、分类、上下文、附件 |
| `bug-solution` | RD | 根因、方案、验收标准与 RD 批准 | 分析根因、修复方式、验收标准 |
| `bug-execute` | RD | 按批准方案修复、推送、提 PR，并验证 | 关联 PR、验证结果、证据附件 |

三个场景以同一条飞书记录（`record_id`）交接，全部无状态：不建本地档案，过程文件放会话临时目录。状态流转由人工在表格中操作。

## 代码

- 分析：所有 Bug 共用全局检出（`repositories[].checkout_path`），bug-solution 每次分析前同步到最新 main，只读。
- 修复：bug-execute 每次从远端最新 main 切 worktree 和 `codex/<摘要>` 分支，修复后推送并解除 worktree。

## 后续自动调度契约

本版没有监听器，场景由用户手动调用。后续服务须处理：记录事件去重、忽略 Agent 自身写回、同一 Bug 串行运行、不同 Bug 并行、等待与恢复、有限重试，以及按真实身份核对批准。

# Bug 表字段与写入规则

提 Bug 写入 Bug 管理表（base `CEHMbNF8Zavq5wsAO3ecrpQ6nPc`，表「Bug 管理」，视图「新框架（一期）」），配置在数据目录 `config.json` 的 `bug_report` 段，缺省时用插件示例配置。只填下表字段，不新增字段；字段通过 `bug_report.field_map` 里的字段 ID 定位，字段改名不受影响。全部写入经 `scripts/feishu.py`，写后回读核对。

## 字段

| 配置键 | 飞书字段 | 类型 | 怎么填 |
|---|---|---|---|
| `title` | Bug 描述 | 文本 | 精简一行「类别：现象」，也是查重依据（同名即视为同一条） |
| `attachments` | 截图、视频、日志 | 附件 | QA 的截图与视频、Web 诊断包或 `web-logs.log`、Computer 召回包、`server-logs.log`；同名同大小的文件不重复上传 |
| `reporter` | 提交人 | 人员 | lark-cli 当前登录用户，建单时自动填 |
| `assignee` | 指派人 | 人员 | 用户在对话里指定的跟进人，`feishu.py assign` 唯一匹配后写入；不唯一或未指定时请用户指定 |
| `status` | 状态 | 单选 | 建单时「未解决」，之后不由本 Skill 修改 |
| `issue_type` | 问题类型 | 单选 | 建单时「bug」 |
| `platform` | 所属端 | 单选 | Agent 判断：`新框架一期-Mac`／`新框架一期-Windows`／`新框架一期-Web` |
| `priority` | 优先级 | 单选 | Agent 按影响面判断；P2 不进「新框架（一期）」视图 |
| `module` | 业务模块 | 单选 | Agent 从现有选项中选最贴近的；没有合适的就不填 |
| `record_time` | 记录时间 | 日期 | 提问时间，按 Asia/Shanghai 写入 |
| `root_cause` | 分析根因 | 文本 | 见下节 |

表中其他字段（修复版本、修复方式、关联 PR、自定义 tag、反馈用户、父记录、备注等）不由本 Skill 填写。

## 「分析根因」的内容

本 Skill 只维护 `【Agent 分析根因】` 标记以下的一块：字段为空时直接写；已有这块时只替换这块；有别人写的内容时保留在前面，这块追加在后面。这块按以下结构写，要让没参与排查的人也能读懂：

```
【Agent 分析根因】
结论：已确认／原因未确认；区分代码复现与现场确认。
根因：触发条件 → 首个错误状态 → 传播 → 用户看到的现象，两到四句。
证据：用到的 Web／Computer／Server 日志及关键记录、复现或测试结果；采集不到的来源与原因。
代码：tutti、tutti-server 的 SHA，关键文件与行号。
待确认：未确认时已排除与仍成立的候选；需要 QA 提供的信息；工具或权限等维护侧问题。
```

再次调用本 Skill 时，从这块读回上次的结论与待确认项继续。
